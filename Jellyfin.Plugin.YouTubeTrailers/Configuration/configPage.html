General

Enable YouTube trailers When off, every trailer endpoint returns 404 and clients fall back to their own behaviour.
Manage yt-dlp automatically Downloads and maintains the official standalone yt-dlp binary for this server's OS — no manual install, no Python.
yt-dlp path Optional. Set only to pin a system yt-dlp; when the file exists it overrides the managed copy.
ffmpeg path Optional. Blank uses the server's bundled ffmpeg.
Cache directory Blank uses a youtube-trailers folder under Jellyfin's cache path. Changing this doesn't migrate existing bundles.

Automatic trailers

Cache trailers before anyone asks for them
Cache trailers for newly added media Builds the trailer in the background whenever the scanner adds or refreshes an item, so it plays instantly the first time. Off by default — a first library scan can queue thousands of jobs.
Delay after an item is added (seconds) Jellyfin announces a new file before the metadata provider attaches the trailer link, so the lookup waits. Raise it if your provider is slow.
Cache every trailer on an item Items often list several (teaser, official trailer, clip). By default only the first — the one clients play — is cached.
Daily sweep of the whole library Runs at 3 AM and caches any linked trailer that isn't on disk yet. Backstop for items imported while the listener was off, or whose metadata landed late. Also runnable on demand from Scheduled Tasks.
Libraries to cache automatically Applies to both the live listener and the daily sweep. Leave everything unticked for all libraries — useful to keep Home Videos or Music Videos from burning build slots.

Playback & quality

Trailer quality All presets pin H.264 + AAC, which is what Apple devices decode in hardware and what can be copied into fMP4 without re-encoding. Lower quality means smaller cache and faster builds.
Custom format selector Raw yt-dlp format expression. Only used while quality is set to Custom. Picking VP9/AV1/Opus here forces a full transcode instead of a stream copy.
Proxy e.g. http://host:port or socks5://host:port. Applied to both yt-dlp and the ffmpeg fetch — use this for geo-blocked trailers, since the download must be proxied too, not just the resolution.
Cookies from browser Fixes "Sign in to confirm you're not a bot" and age-restricted trailers — the most common reason extraction fails. Needs a real browser profile on the server; headless or Docker installs should use a cookies file instead.
Cookies file Absolute path to a Netscape-format cookies.txt exported from a signed-in browser. Takes precedence over the browser option and is the one that works on headless servers.
Build speed limit (× realtime) Caps download speed during builds so a library-wide sweep can't saturate your uplink. 0 = unlimited. Applied to ffmpeg, which is what actually downloads the video. Must be at least 1 — slower than realtime and builds stall.
Extra yt-dlp arguments Space-separated. --cookies FILE or --cookies-from-browser B for age-restricted / bot-checked videos, --extractor-args for PO tokens, --limit-rate. Quote values containing spaces.
Max concurrent builds Server-side trailer builds running at once. Requires a server restart to take effect.
Resolve timeout (seconds) Hard ceiling on how long a client waits for the first playable segment.
VOD grace (seconds) How long a full-screen request waits for the remux to finish so AVKit shows a real scrubber instead of the live UI. Kept small — on timeout playback starts live anyway.

Cache & diagnostics

Max bundle age (days) The daily prune task evicts bundles not used within this many days. 0 = no limit.
Max cache size (GB) Least-recently-used bundles are trimmed until under this size. 0 = no limit.
Remember failures for (minutes) A failed video fast-fails for this long so clients fall back quickly instead of re-running the full timeout. Set 0 while debugging one specific video to retry on every request.
No-segment timeout (seconds) Kills a build that hasn't produced its first segment in time. A dead CDN edge makes ffmpeg reconnect forever without exiting, so without this the client waits out the full resolve timeout.
Verbose logging Logs the full yt-dlp / ffmpeg command line for every invocation at Info level. Noisy, but the fastest way to see exactly what ran on your server.
